# SAM2 掩码引导的叶片拼接

本目录是独立新版代码，依赖模块均在本目录中，不修改或导入 02 的算法模块。需要已生成的 SAM2 掩码，不在运行时加载 SAM2 模型。依赖为 requirements.txt 中的 NumPy、OpenCV、SciPy，以及原流程所用的 ExifTool。

## 运行

从项目根目录执行：

```powershell
python -B src/stitch_blade_refined.py --data-dir 02 --ppm 200
```

图像分析和渲染默认都使用 2 个 worker。12 逻辑核环境下可先尝试：

```powershell
python -B src/stitch_blade_refined.py --data-dir 02 --ppm 300 --analysis-workers 2 --render-workers 3
```

`--analysis-workers` 控制同时分析的图片数，`--render-workers` 控制同时渲染的分块数，`1` 表示串行。程序会把 OpenCV 的可用线程数平均分给各个任务，避免每个任务都再启动全部 OpenCV 线程。也可以用 `--opencv-threads N` 手动指定每个任务内部的 OpenCV 线程数。

并行会增加峰值内存。对于宽约 2200 像素、`--tile-height 512` 的画布，建议分析 worker 从 2 开始，渲染 worker 从 2 或 3 开始；如果内存不足，使用 `--analysis-workers 1 --render-workers 1`，或者减小 `--tile-height`。增加 worker 不保证线性提速，因为图像解码、SIFT 和重映射仍受内存带宽及 OpenCV 内部并行影响。

默认数据目录是脚本所在项目的 `02`，输入为数据目录下的：

- `images`：包含 EXIF 和 LRFTargetDistance 的原图。
- `images_undistorted`：去畸变图片。
- `masks`：同文件名主体的单通道 PNG，尺寸和坐标必须对应去畸变图片。背景为 0，叶片为 255，也支持 0/1 编码。

掩码应仅表示要拼接的一片叶片，并准确排除轮毂、机舱和背景。不能提供彩色叠加图，也不能直接使用未经去畸变的原图坐标下的掩码。缺失、全黑、非二值或尺寸错误的掩码会报错。

其他批次使用 `--data-dir 06` 等参数；当文件结构不同时，分别指定：

```powershell
python -B src/stitch_blade_refined.py --exif-dir 06/images --image-dir 06/images_undistorted --mask-dir 06/mask --output-dir 06/stitch_output_sam2 --ppm 200
```

默认结果写入数据目录下的 `stitch_result`。完整运行只保存：

1. `blade_refined_highres.jpg`：最终拼接图，`--image-format png` 可改为 PNG。
2. `stitch_errors.json`：配准误差、采用的修正模型、修正量、回退原因及输出信息。

不保存投影图、分割诊断图、缓存、预览图或中间数组。`-B` 禁止生成 Python 字节码缓存。相同输出路径的同名结果会被覆盖；不会自动清理目录中已有的其他文件。`--analyze-only` 只分析并写误差报告，不渲染图像。

程序成功结束时会输出从进入主程序到结果保存完成的总耗时：

```text
Saved: 02\stitch_result
Total elapsed: 156.42 s (00:02:36.42)
```

总耗时包括参数处理、EXIF/图片/掩码读取、曲面拟合、配准、渲染、裁切和文件编码。`stitch_errors.json` 的 `output.render_seconds` 只计算并行分块投影与融合阶段，不包含输入读取和最终 JPG/PNG 编码，因此两者数值不会相同。

## 代码级加速

默认渲染会先估计每张照片在叶片纵向坐标中的覆盖范围。每个输出分块只投影与它相交的照片，不再让所有照片参与所有分块；`stitch_errors.json` 中的 `projected_image_tiles` 和 `possible_image_tiles` 可用于查看实际减少的投影量。`--no-footprint-culling` 会关闭这项优化，仅用于生成慢速参考结果。

输出网格到原图的逆投影采用广播标量公式，避免为每个分块建立多份 `高×宽×3` 的世界坐标和相机坐标临时数组。配准求解器还显式提供了每组残差与对应照片变量之间的稀疏关系，使 SciPy 不必对每个变量重复计算所有连接。图片解码、掩码处理和 SIFT 分析按图片并行执行。

在本机 12 逻辑核上，以 02 数据、`--ppm 100 --analysis-workers 2 --render-workers 2` 测得：完整流程由 30.57 秒降至 19.04 秒，约为原来的 1.61 倍速度；分块渲染由 7.99 秒降至 3.04 秒，约为原来的 2.63 倍速度，照片与分块的投影次数由 180 降至 35。关闭和开启覆盖范围裁剪的最终 JPG 字节完全一致，逐像素最大差值为 0。实际收益随照片数量、重叠范围、`ppm`、磁盘缓存和内存带宽变化。

`ppm` 增大时，输出宽高都近似成比例增长，因此渲染像素数和内存通常近似按 `ppm²` 增长。例如同一范围从 100 提高到 300 ppm，画布像素数约为 9 倍；代码优化不能消除这部分分辨率成本。

## 与 02 的算法区别

### 直接利用完整掩码

在 `sam2_alignment.py` 的 `mask_geometry` 中，从原始分辨率的掩码提取实际左右边界，不再根据白色/红色、画面中央位置、最大宽度或三次曲线筛选边界。内部孔洞不作为外轮廓。图像裁切边、零宽度端点不用于双侧配准；完整外轮廓仍用于画布范围，避免因此裁掉叶尖。

边界缺失处不跨越长距离插值。纹理特征则在缩小后的掩码内部计算，用距离变换排除靠近外边缘的 3 个分析像素，避免背景特征混入。`--analysis-scale` 只控制纹理/标记分析，不降低轮廓提取的输入分辨率。

### 两侧分别配准和验证

`contour_constraint` 在激光投影预测的共同区域建立边界约束。`solve` 分别优化两侧的稳健残差，防止左右误差互相抵消。交错采样的一半轮廓用于优化，另一半用于模型选择和验收。纹理与蓝色标记保留原有对应验证。

纵向移动可能缩短真实重叠范围。验证要求至少 16 个有效留出采样位置、至少保留原采样的一半，并覆盖至少 0.3 米；前后误差使用同一有效采样子集。优化中额外惩罚离开有效覆盖区，不能将无覆盖样本直接视为零误差。误差报告列出 `support_fraction`，帮助识别覆盖减少的连接。

### 有限度地增加变换自由度

默认 `--correction-model lateral-affine`，先求平移，再尝试横向尺度和倾斜的小幅修正。设激光投影坐标为 `(u,v)`，每张图以其掩码的中间位置 `(uc,vc)` 为中心：

```text
u' = uc + (1 + scale_delta) * (u - uc) + tx + shear * (v - vc)
v' = v + ty
```

这不是完整旋转、任意仿射变换或真实三维形变。默认横向尺度变化限制在 ±3%，倾斜系数限制在 ±0.01；平移范围由 `--max-shift-m` 控制，默认每轴 ±3 米。优化还有偏向零修正的正则项。

只有小幅横向变换使相关组的平均留出轮廓稳健误差比平移结果下降超过 5%，并通过额外验收，才采用它；否则保留平移结果。相对激光初始位置，两侧中位误差、整体中位误差、稳健误差以及可用点对应误差不能恶化超过 0.03 米；相对平移结果，复杂模型不能恶化超过 0.01 米。没有可靠点对应的图像，不从直线轮廓中猜测纵向移动。

使用 `--correction-model translation` 可关闭尺度和倾斜，进行控制变量比较。

求解不收敛、到达修正边界或平移结果未通过验收时，相关联图像组恢复为零修正，独立组不受影响。零修正指保留本次 LRF 曲面位置，不是切换成根目录的旧平面算法。输入错误不会被此回退逻辑吞掉。

### 掩码参与融合

`MaskBlender` 分开累计叶片与背景颜色，在重采样之前进行掩码预乘，避免背景颜色混入叶片边缘。每个输出位置由视角权重最高的有效图片决定轮廓归属，不把不同图片的叶片掩码直接取并集扩宽叶片。

目前采用视图中心和图像边缘距离作为选择权重，没有实现按内容搜索最小误差接缝。仍有剩余几何误差时，内部纹理或视图切换位置可能存在接缝；掩码融合不能替代几何配准，也不保证所有背景都对齐。

## 误差口径与验证

- `pairs`：每组对应的前后误差；轮廓增加左右边缘误差、稳健误差及有效覆盖比例。
- `summary`：只统计最终采用的约束，分别统计轮廓、纹理和标记。回退组的可测误差仍在逐项记录中保留；无法测量用 `null`。
- `registration`：图像组所用模型、原因、各图修正量及变换中心。图像索引按 `images` 中 EXIF 读取的文件顺序排列，可通过 `pairs` 的文件名核对。
- `mask_input`：掩码目录、原分辨率轮廓输入等信息。

留出轮廓仍来自同一组掩码，并参与了模型选择，不是独立真值测试；蓝色标记可能仅有拟合误差。LRF 拟合误差与拼接误差分别记录，名义像素间距也不代表测量精度。

本批 02 的分析接纳 8 组相邻轮廓和 1 组蓝色标记，轮廓误差中位数汇总从 98.94 降至约 1.71 输出像素（200 px/m）。新版与旧版使用的轮廓范围和有效对应不同，不能只比较两个汇总值来判断谁更精确。
